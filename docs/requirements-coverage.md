# Requirements coverage

Traceability from the proposal's requirements to the code and the evidence that each is met.
**Keep this current.** A row only moves to *Verified* when a named test or a recorded run
proves it; "the code exists" is *Built*, not *Verified*.

Numbering: the proposal lists requirements A, B, C…; the build prompts call them FR1, FR2…
Both are shown. Last reviewed: 2026-10-31 (after section 1 and 2 features).

| Status | Meaning |
| --- | --- |
| **Verified** | An automated test or a recorded run demonstrates it. The evidence is named. |
| **Built** | Implemented and checked by hand (curl, browser), but no automated test yet. |
| **Partial** | Some of the requirement is met; the gap is stated. |
| **Placeholder** | Stand-in behaviour so the system runs; the real implementation is scheduled. |
| **Pending data** | Code written; cannot be run until `creditcard.csv` is available. |
| **Not started** | Nothing exists yet. The prompt that builds it is named. |
| **Conflict** | The design departs from the proposal's wording; needs the supervisor's decision. |

Current state (2026-10-26): data in **PostgreSQL 18** (decision: PostgreSQL, not Firebase —
resolves the FR7 and NFR3 conflicts); real accounts with bcrypt + JWT sessions; a **stub model**
in place of the trained CNN until the dataset is available.

## Non-functional requirements

| ID | Requirement (abridged) | Status | Where | Evidence / gap |
| --- | --- | --- | --- | --- |
| NFR1 (A) | Under 1 s per transaction, receipt to alert; support batch processing | **Built** (batch) / **Partial** (CNN timing) | `web/app/api/transactions/batch/route.ts`, `web/app/api/transactions/ingest.ts`, `simulator/simulate.py --batch`, `inference/app/main.py` | Batch: `POST /api/transactions/batch` takes up to 500 records, scores them in ONE inference call and stores them in ONE database transaction; bad or duplicate records are reported per item without failing the batch (`web/lib/store.test.ts` "batch ingest"; curl with a mixed batch). Recorded run 2026-10-31 (stub model, PostgreSQL, warm dev server, shadow model on): 5,000 transactions at 500/s in batches of 100, finished in 11.5 s; server latency per batch p50 26 ms, p95 154 ms, p99 1,040 ms (one outlier batch) — `simulator/runs/20261031-205343.jsonl`, `training/evaluate_run.py`. Single-transaction path unchanged (800 ms scoring timeout). Repeat with the trained CNN. |
| NFR2 (B) | Tune for F1, precision, recall on the fraud class, not accuracy | **Pending data** | `training/train_cnn.py`, `training/evaluate_run.py` | Threshold chosen to maximise validation F1 on the fraud class; precision, recall, F1, ROC-AUC, PR-AUC recorded in `metadata.json`. Not yet run. Result figures (C2), SMOTE comparison (C3) outstanding. |
| NFR3 (C) | HTTPS; bcrypt passwords; JWT auth + role permissions; parameterised queries; input validated | **Partial** | `web/lib/session.ts`, `web/lib/store.ts`, `web/app/api/auth/session/route.ts` | bcrypt ✓ (cost 12; unknown emails still pay a compare, so timing doesn't reveal which accounts exist). JWT ✓ (HS256, issuer/audience/expiry checked). Role permissions ✓ (FR2). Parameterised queries ✓ (every `pg` query uses `$n` placeholders; the only interpolated SQL is two column names from a fixed map). Input validated ✓ (FR3). Gap: **HTTPS** — local development is plain HTTP; a deployment would terminate TLS. No login rate limiting yet. |
| NFR4 (D) | Clear, scannable UI; effective filtering and sorting | **Partial** | `web/components/*` | Interface built (status chips with icon + label, probability meters, filters, ID search, live updates). Sorting gap as FR9. No usability evaluation yet — protocol in C5. |
| NFR5 (E) | Invalid records rejected without interrupting the pipeline; every prediction stored and traceable | **Built** | `web/app/api/transactions/route.ts`, `web/db/migrations/001_init.sql` | curl: invalid → 400, nothing written, next transaction processed. Inference down → stored as `scoring_failed`, 503. Missing settings → 503 naming `seed-config.ts`, never a default threshold. Database CHECK constraints reject malformed rows even if a code path skips validation. Every row has `model_version` and `threshold_used`. |
| NFR6 (F) | Modular components; model versions recorded so the model can be replaced without changing the rest | **Built** | `models/<version>/metadata.json`, `inference/app/bundle.py` | Training and serving share only the bundle folder; inference loads the newest bundle or `MODEL_BUNDLE`; each prediction records its model version. Registered in the `model_versions` table by `web/scripts/seed-config.ts`; settings follow the model inference reports. |
| NFR7 (G) | Runs in a standard browser and on a standard development computer | **Verified** | — | Whole system (PostgreSQL, inference, web app, simulator) run on a Windows 10 laptop (Intel i7-6600U, no GPU); UI checked in Edge. Fully offline — no cloud service needed for the demonstration. |

## Extensions beyond the proposal (added 2026-10-31)

| Feature | Status | Where | Evidence / caveat |
| --- | --- | --- | --- |
| Per-alert explanation ("Why it was flagged") | **Verified** (method) / **Built** (page) | `inference/app/bundle.py` `explain`, `POST /explain`, `web/app/api/alerts/[id]/explanation/route.ts`, `web/components/explanation-chart.tsx` | Integrated gradients (64 steps, baseline = the average transaction). `inference/tests/test_api.py::test_explain_attributions_add_up_to_the_score`: attributions sum to probability − baseline (residual < 1e-3), match `/predict`, and rank V14 first for the stub. Computed on first view, never on the ingest path; cached only when the serving model is the scoring model. |
| Analyst feedback loop | **Built** | `web/app/api/model/route.ts`, `web/app/api/admin/feedback/route.ts` | Alert precision from analyst decisions on Model health and Reports; admin CSV export in `creditcard.csv` column order (Class = confirmed fraud), audited. **Caveat:** simulator rows come from the test split — adding them to training data would leak the test set. |
| Threshold what-if + cost model | **Verified** (curve) / **Built** (page) | `web/lib/analytics.ts` `thresholdCurve`, `web/app/api/model/threshold-curve/route.ts`, `web/components/threshold-form.tsx` | Precision and recall at every threshold 0.01–0.99 from the active model's labelled traffic; lowest-cost threshold for a chosen review cost (missed fraud costs its amount). `web/lib/analytics.test.ts` asserts the FR6 ≥ boundary on the curve. |
| Drift monitoring (PSI) | **Verified** (method) / **Built** (page) | `web/lib/analytics.ts` `psi` / `driftReport`, `web/components/model-health.tsx` | First vs latest ≤1,000 scored rows of the active model, reference-decile bins, 0.1 / 0.25 cut-offs; Time excluded. `web/lib/analytics.test.ts`: same distribution < 0.1, shifted > 0.25, constant reference still registers drift, shifted feature ranked first. |
| Shadow (challenger) model | **Verified** (scoring) / **Built** (comparison) | `SHADOW_MODEL_BUNDLE`, `inference/app/main.py`, migration `002_monitoring.sql`, `web/lib/analytics.ts` `shadowComparison` | `inference/tests/test_api.py::test_shadow_scores_every_transaction_with_its_own_model`; `web/lib/store.test.ts` stores shadow scores; `web/lib/analytics.test.ts` checks agreement and per-model metrics. Never raises alerts. Live run: 99.0% decision agreement over 8,041 transactions. |
